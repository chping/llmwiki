# **Agent 常用框架架构与核心模块设计**

此文档汇总了多种智能体（Agent）框架的架构特点，并提炼了 Memory、Planner 与 Tool Executor 等核心模块的设计思路。它适用于将多模态与大模型能力引入复杂工程场景，例如 AgenticEDA 等领域。

## **通用 Agent 架构**

一个通用的智能体系统可以抽象为以下流程：

1. **任务理解**：根据用户目标和上下文理解具体任务。
2. **计划制定（Planner）**：根据当前状态和目标生成可执行的步骤序列。
3. **状态与记忆（Memory）管理**：维护短期与长期上下文，在多轮任务中复用。
4. **工具调用（Tool Executor）**：安全地调用外部工具或 API 完成子任务，并处理结果与异常。
5. **观察与反馈**：解析工具执行结果，更新任务状态并决定下一步行动或输出。

这种闭环流程强调模型不仅生成答案，还要进行决策、执行、验证和自我修正【21†L1-L14】。

## **主流 Agent 框架对比**

### **LangGraph**

- **核心思想**：将智能体流程建模为有状态的有向图，每个节点执行具体逻辑，每条边控制状态转移。通过显式状态管理支持复杂工作流与长任务。
- **特点**：适合需要明确状态管理的复杂任务；易于处理循环、回退和人工介入。
- **适用场景**：例如在硬件设计流程中，实现 RTL 生成→Lint→调试→回归测试等明确状态转换的闭环。

### **AutoGen**

- **核心思想**：采用多智能体对话协作的方式，每个 Agent 执行不同角色。通过配置 Agent 的模型、工具和策略，实现专家协作解决复杂问题。
- **特点**：便于模拟专家之间的讨论与审查；支持代码生成与多轮协商。
- **适用场景**：适合在项目开发或研究中，将不同职能拆分成多个 Agent（如 Spec Agent、Verification Agent、Review Agent 等）协同解决问题。

### **CrewAI**

- **核心思想**：通过角色、任务和 Crew 定义协作模式，内置记忆、知识和 guardrails（安全机制）。
- **特点**：适合角色分工明确、流程较固定的业务场景；框架支持跨任务的记忆和知识沉淀。
- **适用场景**：面向执行已有流程或产品化任务，如需求分析、工具调用和报告生成等。

### **OpenAI Agents SDK**

- **核心思想**：提供统一的 Agent 定义和工具调用接口，支持运行时行为、审批和追踪（tracing）。
- **特点**：强调安全执行和可追溯性；易于接入生产环境，包括多 Agent 接力、人工审批和 Guardrails。
- **适用场景**：适合需要严格审计和安全控制的应用，例如生产环境的 EDA 工具编排。

## **Memory 设计思路**

Memory 不只是简单记录历史对话，而是支撑智能体长期运行的重要结构。根据用途可分为：

| **Memory 类型** | **说明**                                                  |
| --------------- | --------------------------------------------------------- |
| **短期记忆**    | 保存当前任务的上下文，例如当前 RTL 文件和最近的工具日志。 |
| **长期记忆**    | 存储项目长期知识，如规范、模型参数、接口定义和执行经验。  |
| **工具记忆**    | 记录工具调用历史、失败原因和成功参数，供未来决策参考。    |
| **语义记忆**    | 将非结构化文本转化为向量或结构化知识，便于检索与推理。    |

良好的记忆系统应具备：可检索、可压缩、可过期和可追溯等特性。设计时应分层存储，不把所有上下文塞入单一提示，而是通过向量检索、结构化数据库等方式按需加载。

## **Planner 设计思路**

Planner 决定智能体下一步行动，是 Agent 中的核心决策模块。设计 Planner 时可考虑以下几种策略：

- **LLM Planner**：由大模型直接生成执行计划，灵活但不确定性强。
- **规则/状态机 Planner**：用有限状态机或规则定义流程，适合对流程控制要求高的场景。
- **分层 Planner**：先拆分大任务，再为子任务选择不同执行策略。
- **混合 Planner**：结合规则和模型，既保证流程安全，又利用模型处理复杂决策。

在 EDA 等高风险领域，建议使用 **混合 Planner**：

1. 用有限状态机控制关键流程（如 Lint 未通过不得继续），确保工具调用顺序正确；
2. 使用 LLM 提出修复建议、代码生成等灵活任务；
3. 为每个动作设定前置条件、成功/失败标准和最大重试次数。

## **Tool Executor 设计思路**

Tool Executor 是 Agent 与外部工具交互的执行层。它不仅是简单的函数调用，还应包含安全和治理机制。主要设计原则包括：

- **接口清晰**：每个工具应定义输入、输出和错误模式，如 `run_lint(rtl_files, top_module) → {status, errors, warnings}`。
- **安全隔离**：在调用可能有副作用的工具时使用沙箱和权限控制，防止误操作。
- **错误处理**：支持超时、重试和错误日志记录，必要时引入人工审批。
- **审计追踪**：记录每次工具调用的参数和结果，便于回溯和调试。
- **人工审批**：对关键操作（如修改 Golden 数据或提交代码）设置审批流程。

对 AgenticEDA 等业务，Tool Executor 可能需要管理多种 EDA 工具（如 Verilator、Synthesis、P&R、STA 等），因此必须为每个工具提供受控的接口和回滚策略【21†L1-L14】。

## **总结**

各类 Agent 框架为开发智能体提供了不同的抽象和工程能力，但核心仍围绕 **理解任务–制定计划–执行工具–记忆管理–反馈修正** 这一闭环。Memory、Planner 和 Tool Executor 是智能体系统的关键，它们决定了系统在复杂、多步骤任务中的稳定性和可扩展性。针对 EDA 等高可靠性领域，需要在框架选择和模块设计上更加注重流程控制、安全执行和可追溯性。

根据这些原则，AgenticEDA 技术负责人应结合团队实际需求选用合适的框架，并针对特定任务设计合理的记忆管理、规划策略和工具执行机制。
