# 数字芯片设计入门教程与开源练习项目

## 1. 主题概述（Overview）

本主题整理数字芯片设计的新手学习路线与适合练习的开源 demo 项目，重点覆盖从数字逻辑、[[Verilog]]、[[RTL]] 仿真到开源 ASIC 后端流程的渐进路径。推荐顺序是“数字逻辑 → Verilog/仿真 → RTL 小项目 → CPU/SoC → [[ASIC Flow]]”，避免一开始就直接进入大型 SoC 或复杂处理器核。

## 2. 背景与意义（Background）

数字芯片设计的学习难点不只在语法，而在于同时理解硬件并发、时序约束、测试平台、综合结果、后端实现和系统软件协同。对新手来说，最有效的路径通常不是先读完整工业手册，而是用可运行、可验证、可观察波形的小项目逐步建立直觉，再进入 [[RISC-V]] CPU、Tiny Tapeout 或 OpenROAD 这类更接近真实芯片流程的项目。

## 3. 核心问题（Key Problems）

- 如何从布尔逻辑、组合逻辑、时序逻辑和 FSM 过渡到可综合的 RTL 设计。
- 如何区分“会写 Verilog 语法”和“能写出可综合、可验证、可实现的硬件”。
- 如何通过开源工具链完成仿真、综合、布局布线和 GDS 生成。
- 如何选择规模合适的 demo 项目，避免被大型 CPU/SoC 工程复杂度劝退。

## 4. 方法与技术路线（Methods）

- 第一阶段：通过 [HDLBits](https://hdlbits.01xz.net/) 刷 Verilog 小题，覆盖门电路、组合逻辑、时序逻辑、FSM、RAM、FIFO 等基础模块。
- 第二阶段：学习 [Nand2Tetris](https://www.nand2tetris.org/) 或 [MIT 6.004 Computation Structures](https://ocw.mit.edu/courses/6-004-computation-structures-spring-2009/)，建立从逻辑门到处理器和系统结构的整体理解。
- 第三阶段：用 Icarus Verilog、Verilator、GTKWave 等工具写 testbench、跑仿真、看波形，重点练习“设计-验证-修正”的闭环。
- 第四阶段：选择 Tiny Tapeout 模板或 OpenROAD 示例设计，把简单 RTL 送入开源 ASIC flow，理解综合、floorplan、placement、CTS、routing 和 GDS 输出。
- 第五阶段：阅读 PicoRV32、SERV 或 OpenMIPS 这类小型 CPU 核，学习指令执行、总线接口、流水线、冒险处理和 SoC 集成。

## 5. 核心教程资源（Tutorials）

- [HDLBits](https://hdlbits.01xz.net/)：最适合 Verilog 入门刷题，从基础语法到 FSM 和小型模块都有在线判题，适合作为第一站。
- [Nand2Tetris](https://www.nand2tetris.org/)：从 NAND 门一路搭到 CPU、汇编器、编译器和小游戏，偏计算机系统理解，不是工业 RTL 风格，但能建立强直觉。
- [MIT 6.004 Computation Structures](https://ocw.mit.edu/courses/6-004-computation-structures-spring-2009/)：系统讲数字系统、组合逻辑、时序逻辑、FSM、处理器和系统结构，比 Nand2Tetris 更接近大学计算机工程课程。
- [一生一芯 YSYX](https://ysyx.oscc.cc/project/intro.html)：中文资源里强度较高的开源处理器芯片实践项目，目标是设计 [[RISC-V]] 处理器并理解从软件到硬件的全链路。
- [Tiny Tapeout](https://github.com/TinyTapeout)：适合体验“自己写的 Verilog 真的能变成 ASIC”的完整流程，有项目模板、示例和社区提交。
- [Zero to ASIC](https://www.zerotoasiccourse.com/)：面向开源 ASIC 入门的课程资源，适合在会写基本 RTL 之后理解流片流程。
- [OpenROAD Flow Scripts Tutorial](https://github.com/The-OpenROAD-Project/OpenROAD-flow-scripts/blob/master/docs/tutorials/FlowTutorial.md)：可用 `gcd` 这类小设计跑完整 RTL-to-GDS 流程，适合理解后端各阶段产物。

## 6. 新手练习项目（Demo Projects）

- [TinyTapeout templates](https://github.com/TinyTapeout)：建议从计数器、PWM、UART echo、VGA 小图案、小游戏逻辑等小项目开始，目标清晰且贴近 ASIC 提交流程。
- [OpenROAD-flow-scripts](https://github.com/The-OpenROAD-Project/OpenROAD-flow-scripts)：先跑内置 `gcd` 示例，观察综合、floorplan、placement、CTS、routing、DRC/LVS 前后的中间文件和版图结果。
- [PicoRV32](https://github.com/YosysHQ/picorv32)：成熟的小型 [[RISC-V]] CPU，适合学习指令执行、总线接口、testbench 和 SoC 集成。
- [SERV](https://github.com/olofk/serv)：极小的 bit-serial [[RISC-V]] CPU，适合研究如何用很少逻辑实现可用处理器。
- [OpenMIPS](https://github.com/grantae/OpenMIPS)：MIPS 教学资料较多，适合学习五级流水线、取指、译码、冒险、转发和异常处理。
- [open-fpga-verilog-tutorial](https://github.com/Obijuan/open-fpga-verilog-tutorial)：使用开源工具学习 Verilog 和 FPGA，小项目导向，比直接上 ASIC 更轻。

## 7. 推荐练习顺序（Learning Path）

1. 在 HDLBits 刷到 FSM、RAM、FIFO，先把组合逻辑、时序逻辑和状态机写顺。
2. 自己实现 5 个小模块：按键消抖、PWM 呼吸灯、UART TX/RX、同步 FIFO、SPI master。
3. 用 Icarus Verilog 或 Verilator 写 testbench，并用 GTKWave 查看波形。
4. 选择一个 TinyTapeout 模板，把一个小模块改成可提交项目。
5. 跑 OpenROAD 或 OpenLane，把简单 RTL 变成 GDS，理解 [[ASIC Flow]] 的每个阶段。
6. 阅读 PicoRV32 或 SERV，再尝试修改外设、总线接口或指令子集。

## 8. 核心结论与共识（Key Insights）

- 最稳的新手路线是 HDLBits → TinyTapeout 小项目 → OpenROAD `gcd` → PicoRV32/SERV。
- 学数字芯片设计不能只学 Verilog 语法，必须同时练习 testbench、波形分析和综合后结果检查。
- CPU/SoC 项目很适合建立系统观，但不适合作为第一个 RTL 项目。
- Tiny Tapeout 和 OpenROAD 让个人学习者可以低成本接触真实 ASIC flow，是从 FPGA/仿真走向芯片实现的重要桥梁。

## 12. 发展趋势（Trends）

- 开源 EDA 工具链正在降低数字芯片设计的入门门槛，学习者可以在个人电脑或云环境中完成从 RTL 到 GDS 的基本流程。
- [[RISC-V]] 生态让教学型 CPU、轻量级 MCU 和开源 SoC 更容易复用和对比。
- Tiny Tapeout 等社区流片项目正在把“写一个能制造的小芯片”变成新手也能逐步接近的实践目标。

## 13. 未解决问题（Open Problems）

- 开源工具链的安装、版本兼容和 PDK 配置仍可能消耗大量时间。
- 初学者容易把仿真通过误认为设计可靠，但真实芯片设计还需要时序、面积、功耗、复位、CDC 和验证覆盖率等更多检查。
- 从小型 demo 过渡到可维护的 SoC 工程，需要额外学习总线协议、软件栈、验证方法学和工程组织。
